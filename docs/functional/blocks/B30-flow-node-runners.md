## Responsibility

A `NodeRunner` ([B28](B28-flow-engine.md)) executes one node and returns a `NodeOutcome`; it never picks the next node and never changes task status. Each of the five node kinds has a runner here. The runners are the seam where the generic engine meets the orchestrator's collaborators (router, check runner, git, notifier, store), injected once per execution unit through `NodeServices`/`NodeInputs`. This block also covers the per-node prompt assembly, the `output_artifact` post-processing, the output-policy containment, and the wiring that builds the runner registry.

## Behavior

### Agent node

`AgentNodeRunner.run` ([agent.py:67](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L67)) resolves the route from the node's `provider` (else the global primary) using the node's own id as the request identity (`resolve_route(node.id, …)`, [agent.py:69](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L69)), builds an `AgentRunRequest` whose `node_id` is `node.id`, runs it through the router ([B17](B17-agent-router-and-fallback.md)), records a `node_runs` row, and returns an unconditional `done` outcome carrying the agent output (so the post-node hook can persist an `output_artifact` slot / read the decomposition contract). Infra-exhaustion (no provider completed the run) raises `NodeInfraError` ([agent.py:235-241](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L235)); a quality-failed result flows on for a downstream evaluator/checks node to judge (`_agent_outcome`, [agent.py:485](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L485)). A `best_effort` node tolerates infra-exhaustion and continues with no output ([agent.py:74-79](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L74)) — the §5.2 minimal-summary fallback.

Core-owned behaviors wrap the run, all **data-driven, never keyed by stage name**:

- **Max-turns gate** (idea 29, opt-in via `agents.providers.claude.max_turns_gate`) — every provider invocation goes through `_invoke_with_turn_gate` ([agent.py](../../../src/wastech_orchestrator/core/flow/nodes/agent.py)). When the gate is on and a Claude run returns the structured `error_max_turns` failure (`NormalizedError.failure_subtype`, surfaced by [B18](B18-agent-providers.md); detected by `_is_max_turns`), the runner pauses for a durable `HumanGate` **continue/stop** approval (`_turn_limit_signal`, a synthesized `HumanInputSignal` carrying node id only) instead of letting the failure flow on. Continue → re-invoke resuming the same session (`_same_provider_session_id`) with a fresh turn grant (the adapter re-passes `--max-turns` every invocation); deny / timeout / transport → STOP, returning the failed outcome unchanged (terminal exactly as with the gate off). No resume cap in v1 — each continue needs a fresh approval and timeout→STOP bounds an unattended loop. Fail-closed across restart: a turn-gate left `waiting` (its own `turn_gate_interaction_path` artifact, distinct from the embedded-HITL/guardrail files) is resolved at node entry **before** the provider runs, so a restart never silently auto-continues; a denied/unanswered pending decision fails closed to `NodeManualRequired`. The gate flag reaches the runner via `NodeServices.max_turns_gate`, resolved once by the orchestrator from the claude provider block ([B06](B06-orchestrator-pipeline.md)).
- **Embedded HITL** ([agent.py:95](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L95)) — a node opts in by declaring `hitl` with `allow_question`/`allow_approval` (`_wants_hitl`, [agent.py:507](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L507)); the typed-output schema/parser is selected by the node's `OutputContract` (`_contract`, [agent.py:160](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L160)), also never a stage name. If the typed output carries a human question/approval, the runner does at most one durable round-trip via `HumanGate` and re-runs the node with the answer, resuming a persisted interaction after a restart. The re-run **resumes the first run's agent session** (it does not recreate it) so the agent continues the same conversation with the operator's answer rather than re-deriving from scratch — see session continuity below. A second signal after an answer fails closed to `NodeManualRequired` ([agent.py:125](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L125)).
- **Dangerous-diff + output-containment guard** ([agent.py:246](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L246)) — after a `workspace-write` edit the runner writes `{diff_path}` and: (1) for a document/report `output_policy`, fails closed if any change escaped the report directory (`_apply_output_containment_guard`, [agent.py:293](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L293)); (2) classifies the diff ([B14](B14-dangerous-diff-guardrail.md)) and, if a deletion/dependency change is found, requires a durable human approval — any prior in-task approval of the **identical** dangerous diff (same risk + exact path set) counts, whether a planning pre-approval or an earlier workspace-write node's guardrail approval (`_already_approved_in_task`, [agent.py:350](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L350)), so a later editing node such as `documentation` does not re-prompt for an already-cleared change — reconsidering once on denial before failing closed (`_reconsider`, [agent.py:336](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L336)). The guardrail and embedded-HITL interaction artifacts are keyed by `node.id` ([B12](B12-hitl-and-typed-output.md)).

The request grants network iff the flow declares a `network_policy` ([agent.py:410](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L410)). Editing-session continuity is realized here: an `editing_lineage` node resumes the unit's stored session only when the same provider produced it (`_resume_session_id`, [agent.py:454](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L454)) and persists it after success (`_persist_session`, [agent.py:473](../../../src/wastech_orchestrator/core/flow/nodes/agent.py#L473)) — the raw session id lives only in `state.db` ([B07](B07-state-machine-and-store.md), `editing_lineage`). `lineage_affinity` makes `fixing` and `documentation` continue the session `implementation` established.

The HITL round-trip adds a second, orthogonal source of session continuity: the post-answer re-invoke threads the first run's `session_id` directly (`_same_provider_session_id` → the `_invoke`/`_build_request` `resume_session_id` argument; the same helper the max-turns gate's continue uses), so **any** HITL-capable node resumes its session across the human round-trip regardless of `session_scope` — not just `editing_lineage` nodes. An explicit HITL `resume_session_id` takes precedence over the editing-lineage lookup; for an editing-lineage node the two agree (the explicit value is the just-persisted session). Resume is gated to the **same provider**: it only resumes when the first run's `provider_used` equals `route.primary`, because the re-invoke leads with the primary and a session cannot be resumed across providers (the router also drops `session_id` on a cross-provider fallback). The dangerous-diff denial re-run (`_reconsider`) needs no special threading — it runs the `editing_lineage` author nodes, which already resume via `_resume_session_id`. This in-process resume holds within one run only: after a process restart the first-run session id is gone (a `fresh_disposable` node has no durable session slot — by design), so the re-entered round-trip honestly falls back to a fresh session plus the persisted human-answer context file.

### Evaluator node

`EvaluatorNodeRunner.run` ([evaluator.py:54](../../../src/wastech_orchestrator/core/flow/nodes/evaluator.py#L54)) runs the evaluator's `role_file` prompt read-only and maps its structured verdict to an outcome (`_verdict`, [evaluator.py:132](../../../src/wastech_orchestrator/core/flow/nodes/evaluator.py#L132)): a blocking finding → `rework`, otherwise `accept`. Blocking means severity `high` (raw `high`/`critical`/`blocking`); `medium`/`low` are advisory only — the routing (`_is_blocking`) and the carried `Finding.blocking` flag agree on this (one definition, `_BLOCKING_SEVERITIES`). It writes the findings artifact (`review/findings.json`, exposed downstream as `{review_path}`, [evaluator.py:118](../../../src/wastech_orchestrator/core/flow/nodes/evaluator.py#L118)) and an immutable `in_flow_verdict` row in `evaluations`. Two evaluator shapes share one mechanism:

- **Blocking** (`blocking: true`, e.g. `review`) — reworks every time it finds a blocking issue; the engine's named-loop budget bounds the cycles (exhaustion → manual).
- **Non-blocking self-capping** (e.g. `test_quality`) — reworks until its own `max_rework_per_stage` is spent, **counted from the immutable `in_flow_verdict` rows** (`count_rework_verdicts`, [evaluator.py:146](../../../src/wastech_orchestrator/core/flow/nodes/evaluator.py#L146)), then accepts — never manual. There is no mutable counter, so the core stays domain-free.

A `resume_own_lineage` evaluator (the research critic) resumes its own durable session across rework rounds, persisted in `node_lineage` keyed by `(task_id, node_id, subtask_order)` (`_resume_own_session`/`_persist_own_lineage`, [evaluator.py:188-228](../../../src/wastech_orchestrator/core/flow/nodes/evaluator.py#L188)).

When **no provider could run** the evaluator (infra-exhaustion), it raises `EvaluatorInfraError` — a `NodeInfraError` subclass — rather than the plain `NodeInfraError` an agent node raises ([evaluator.py:89-95](../../../src/wastech_orchestrator/core/flow/nodes/evaluator.py#L89)). The distinction lets the orchestrator degrade an evaluator that could not _run_ to terminal `manual_action_required` (the green diff is shippable — branch preserved for the operator) instead of discarding it as `failed`, while an agent node whose infra exhausted has no usable result and stays `failed` ([B06](B06-orchestrator-pipeline.md)).

### Checks node

`ChecksNodeRunner.run` ([checks.py:63](../../../src/wastech_orchestrator/core/flow/nodes/checks.py#L63)) dispatches on `node.checker`; every checker maps to the same `pass`/`fail` outcome so the engine needs no per-checker case:

- **`command_profile`** ([checks.py:79](../../../src/wastech_orchestrator/core/flow/nodes/checks.py#L79)) — diff-selects which of the resolved command sets to run (`select_check_sets(self._in.check_sets, git.changed_code_paths_since_base())`, [B23](B23-check-discovery.md)) and runs them all through the Check Runner ([B24](B24-check-execution.md)). Selection reads the **base-inclusive** changed set (committed-since-base + uncommitted) rather than the working-tree-only staging set, so a decomposed subtask whose code is already committed is still checked instead of passing vacuously. An empty selection (empty diff, or no `command_sets`) is a vacuous `pass` ([checks.py:85-87](../../../src/wastech_orchestrator/core/flow/nodes/checks.py#L85)). It then maps the aggregate `CheckOutcome`: `any_launch_failed or nothing_ran` → `NodeManualRequired` (node-run status `incomplete` — a required toolchain absent, or every check skipped; changed code is not handed on unchecked, and this precedence wins over a quality failure, [checks.py:89-100](../../../src/wastech_orchestrator/core/flow/nodes/checks.py#L89)); else `any_quality_failed` → `fail`→`fixing` ([checks.py:101-102](../../../src/wastech_orchestrator/core/flow/nodes/checks.py#L101)); else `pass`. **Mutation guard (P2.4):** it snapshots the working tree before/after; a _passing_ check that mutated commit-candidate files fails closed to manual review ([checks.py:103-113](../../../src/wastech_orchestrator/core/flow/nodes/checks.py#L103)) — a green-but-dirtying check must not pass silently. This is core-owned and cannot be disabled by the flow. (The former launch-failure re-resolve hook and `CheckLaunchError` were removed with the checks-monorepo change.)
- **`citation`** / **`dependency_scan`** — delegate to the read-only checkers ([B32](B32-flow-checkers.md)); the mutation guard does not apply.

### HITL node and the human gate

`HitlNodeRunner` ([hitl.py:39](../../../src/wastech_orchestrator/core/flow/nodes/hitl.py#L39)) is a bare human gate with no agent stage, keyed by the node id (not a `Stage`) via `node_interaction_path`. `signal: approval` branches `route:approve` / `route:deny`; `signal: question` proceeds `done` once a non-empty answer arrives (`_outcome`, [hitl.py:119-123](../../../src/wastech_orchestrator/core/flow/nodes/hitl.py#L119)). `HumanGate` ([human_gate.py:27](../../../src/wastech_orchestrator/core/flow/nodes/human_gate.py#L27)) is the shared primitive behind the embedded refinement/planning HITL, the dangerous-diff approval, and this node: it takes the `node_id` as the interaction key, sends one correlated prompt, persists a durable `waiting` artifact, waits against the persisted deadline, and records the answer; a restarted process resumes the `waiting` interaction (`resume`, [human_gate.py:67](../../../src/wastech_orchestrator/core/flow/nodes/human_gate.py#L67)). Fail-closed: a missing notifier, timeout, transport error, or invalid response raises `NodeManualRequired`.

### Publish node

`PublishNodeRunner` ([publish.py:43](../../../src/wastech_orchestrator/core/flow/nodes/publish.py#L43)) maps the flow's `PublishingPolicy` to idempotent git operations ([B22](B22-git-manager.md)) — publishing is the orchestrator's sole responsibility; providers and flows never touch git. `pull_request` / `documentation_pull_request` call finalize (move the task file + write the committed summary, the PR body), then commit code, commit the audit trail, push, and open the PR — each idempotent via `publish_operations` ([publish.py:94-124](../../../src/wastech_orchestrator/core/flow/nodes/publish.py#L94)). `private_control_workspace_report` stores the report under the gitignored `.worc/` workspace and touches git not at all, failing closed if the report would be git-trackable ([publish.py:126](../../../src/wastech_orchestrator/core/flow/nodes/publish.py#L126)). A git failure **after** finalize already moved the task file raises `NodeManualRequired` (a resumable manual stop via `rerun --continue`) rather than a terminal failure, so a done-committed task is neither mislabeled nor stranded ([publish.py:64-82](../../../src/wastech_orchestrator/core/flow/nodes/publish.py#L64)).

### Prompt assembly, output artifacts, output policy

- `render_role_prompt` ([prompt.py:41](../../../src/wastech_orchestrator/core/flow/prompt.py#L41)) reads the node's `role_file` from inside the flow directory (defense-in-depth on top of the load-time traversal check) and substitutes only allowlisted **path** variables via the fixed core renderer ([B15](B15-prompt-templates.md)) — never task bodies, diffs, logs, env, or secrets.
- `apply_output_artifact` ([postprocess.py:50](../../../src/wastech_orchestrator/core/flow/postprocess.py#L50)) writes an agent node's declared `output_artifact` slot (`enriched_spec` → `task.enriched.md`, `plan` → `plan.md`, `summary` → `summary.md`) and threads the path into the downstream `NodeInputs` (so the next node gets `{plan_path}` etc.). `read_decomposition` ([postprocess.py:82](../../../src/wastech_orchestrator/core/flow/postprocess.py#L82)) reads the proposed_by node's decompose/subtasks contract and applies the deterministic gate ([B11](B11-task-decomposition.md)).
- `resolve_output_policy` ([output_policy.py:53](../../../src/wastech_orchestrator/core/flow/output_policy.py#L53)) maps a scalar `OutputPolicy` to a `ResolvedOutputPolicy` (the per-task report directory, required files, privacy): `repository_document` → `docs/research/<task-id>/`, `private_control_workspace_report` → `.worc/security-reports/<task-id>/` (never committed), `code_change` → no report directory.

### Wiring

`build_node_services` ([wiring.py:40](../../../src/wastech_orchestrator/core/flow/wiring.py#L40)) / `build_node_inputs` ([wiring.py:92](../../../src/wastech_orchestrator/core/flow/wiring.py#L92)) turn the orchestrator's live `_Pipeline` and collaborators into the data bundles the runners read; keeping this out of `orchestrator.py` keeps the node layer free of an orchestrator import. There is **no node→`Stage` map**: each runner uses `node.id` directly as the request identity (`AgentRunRequest.node_id`), the output-schema/HITL contract selector, and the interaction/observability path key (wiring.py module doc, [wiring.py:10-12](../../../src/wastech_orchestrator/core/flow/wiring.py#L10)). Routing is node-based — `build_node_services` does not take a flow snapshot and translates no node into a pipeline stage.

## Invariants & guarantees

- **Runners never transition** — they return a `NodeOutcome`; the engine ([B28](B28-flow-engine.md)) moves execution and the orchestrator moves the [B07](B07-state-machine-and-store.md) status.
- **Git is orchestrator-only** — only the publish node calls the `GitPort`, and only the orchestrator wires it ([base.py:204-206](../../../src/wastech_orchestrator/core/flow/nodes/base.py#L204)).
- **Raw sessions only in `state.db`** — `editing_lineage` / `node_lineage` are the sole stores of raw provider session ids; redacted everywhere else ([B21](B21-secret-redaction.md)).
- **Containment fails closed** — output-policy and dangerous-diff guards raise `NodeManualRequired` rather than publishing a risky change.
