## Initial context

The trigger was a single content run (`blog-review-happy-in-my-misfortunes-4`) whose token cost was dominated by the supervisor and inflated by broken accounting. Two analyses frame the work: the token analysis (F1–F5) and [../../analysis/2026-07-16-supervisor-token-optimization-options.md](https://github.com/VladimirMakarevich/wastech-orchestrator/blob/main/docs/analysis/2026-07-16-supervisor-token-optimization-options.md) (variants A–I, target architecture §6, phasing §8).

Three findings drive everything here:

- **Accounting was wrong before anything could be tuned.** Codex resume usage is cumulative for the whole session, so naive per-node summation double-counted (a reported 424 163 vs. a true 282 699 input tokens, +50%); Claude's real input is split across three fields that were never summed. No honest token A/B is possible until usage is normalized and persisted per attempt.
- **The supervisor is the largest Claude-context consumer.** On the analyzed run seven supervisor calls spent 480 293 input tokens (~70% of the task's Claude input); six of the seven were intermediate observations, and the supervisor is advisory-only (it never routes). The savings are large and safe — but only if `finalize` stops depending on the warm session first.
- **Content flows resume heavy sessions for tiny edits.** `polish` re-ran a 31–37k-token transcript four times for a one-word edit because it inherited `revise`'s editing lineage; the session-scope docs never warned that resume grows input tokens on every turn.

All five items are done. P1 confirmed in code what made it safe: the packet is independent of whether observations ran (`steps[].message` comes from each node's own `<node_id>.out.md`, not from an observation row), so `observe.mode: none` keeps a full summary. P2 closed the one thread P1 left open by answering it in the negative — it introduced no observation-shaped row, because `node_runs` already **is** the step record and a second durable writer of the same facts is what P2-D2 exists to prevent; what P2 did instead was move the _assembly_ of those facts out of the LLM class into the flow recorder, so the packet and the observation gate read one derivation rather than each making their own.

**The decision tags stay in this folder.** `P0-D3`, `X1`, `P1-D7` and the like are navigation for these documents, not explanation, and [coding-style.md](../../../.agents/rules/coding-style.md) forbids them in code comments, docstrings, log records, exception messages and anything under `packaged/`. What travels into the code is the reason ("the packet is built only from durable state so a revive reproduces the same summary"), never the identifier. The campaign is unusually tag-dense, so this is the easy mistake to make in every phase.

**P3 was added 2026-08-03 and sits after all five.** It is not on the savings critical path — P0–P2 already delivered them — but it depends on all three supervisor items: it renders its deterministic report from P0's `PacketFacts` over P2's recorder-owned step facts, and its off switch exists precisely to sidestep the P1 cadence rule (`observe.mode: none` globally is refused for a flow that declares `events`). It also reverses part of two of this campaign's own deliberate non-goals; [follow_ups.md](follow_ups.md) records how far.

> **Actualized 2026-08-03 (same day) — P3 is `accepted`.** Its three forks were closed and a fourth was found by the mandatory re-verification pass: **Q1** (memory) went to the _softer_ option the doc argued against — memory is quenched in the config loader with a warning rather than refused fatally, which the doc now records together with the "no silent drift" cost it accepts; **Q4** (new) removes D6's read-time gating derivation, because `_to_finding` collapses `blocking: true` / `critical` / `high` into one persisted `high`, so a rank comparison at read time cannot reproduce the gate's own decision under `gate_severity: critical|blocking` — the evaluator now persists a `gating` flag on each finding instead (which also voids risk R7 and needs no DB change). **Q3** grew: the new renderer replaces `write_minimal_summary` in _every_ terminal and `summary.json` unifies on one key set, since nothing in the code reads that file — the two diverging formats were held together by tests alone.
