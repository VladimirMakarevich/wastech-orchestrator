# Doc-impact notes for the `main` docs reconstruction

Status: **inventory** Date: 2026-07-27 Owner: Vladimir Makarevich

`dev` deliberately carries no derived documentation: the descriptive documents (`worc_architecture.md`, `configuration.md`, `cookbook.md`, `glossary.md`, `operations.md`, the site) live on `main` and are reconstructed there from the merged `dev` diff as a separate task ([.agents/rules/git-workflow.md](../../.agents/rules/git-workflow.md) §A). AGENTS.md therefore asks each `dev` change to leave a one-line doc-impact note instead of creating those files.

This is where those notes accumulate. It exists because a bare diff does not say _which page now contradicts the code_, and because the campaign folders that collected the notes are deleted once their items land — the reconstruction task runs later than that.

**How to use it:** work top-down, and delete a section once the reconstruction has consumed it. A note that survives its reconstruction is worse than no note.

## `deep_research` post-mortem campaign (P0.1 … P3.10, 2026-07-25 → 2026-07-27)

- **P1.4 — audit coverage gate.** The node-output channel now spans evaluators (`configuration.md`, the flow-authoring page's prompt-variable table); `deep_research`'s graph gained three nodes and a gate (`worc_architecture.md`, `cookbook.md`).
- **P1.4a — read-only git evidence.** A new `security.*` key and a new per-node flow field (`configuration.md`, the flow-authoring page); and **the `read-only` permission profile no longer implies "no shell"** (`worc_architecture.md`, `glossary.md`) — that last one is a definition change, not an addition.
- **P2.8 — node output handoff.** A new per-node flow field `output_file` (`configuration.md`, the flow-authoring page's node-field table); the node-output channel can now carry a produced document rather than the node's message (`worc_architecture.md`'s handoff description, `glossary.md` if it defines the channel); `citation.json` gained `manifest_path` (`configuration.md`'s checker section).
- **P2.9 — deliverable containment.** No engine change, but the `repository_document` story changes in prose: the structuring node writes nothing and the deliverable directory holds only the deliverable (`cookbook.md`, `worc_architecture.md`).
- **P3.10 — flow and config hygiene.** `deep_research`'s graph gained a `command_profile` gate and lost `refinement`'s predicate (`worc_architecture.md`, `cookbook.md`); and the two `when:` facts are now documented as what they actually resolve (`configuration.md` — the one an operator is most likely to misread).

### From the 2026-07-27 follow-ups walkthrough

One behavior change and four shipped-doc clarifications. The derived tree currently **contradicts** the first one, so it is not merely missing:

- **WRI-009 no longer always parks.** Git control-state drift on a `read-only` node holding the git-evidence grant now warns and continues; every other profile still parks. `worc_architecture.md`'s WRI-009 description states the terminal outcome unconditionally, and `glossary.md` must not list control-state drift as an unqualified `manual_action_required` trigger. The signal is `NodeOutcome.read_only_git_drift` (carrying the redacted aspect summary, not a bool) and a third synthetic trace label `TRACE_READ_ONLY_GIT_DRIFT` joined `TRACE_REWORK_EXHAUSTED` / `TRACE_READ_ONLY_WRITE` — wherever the ⚠️ trace labels are enumerated, that list is now short one.
- **`security.allow_git_evidence` is a grant switch, not a kill switch.** With it off, a Codex `read-only` node still reads git history, so the provider asymmetry persists (`configuration.md`'s security section).
- **`skip_if_unavailable` is not an escape hatch.** Skipping the only selected set parks the task exactly as a launch failure would; disabling the node per task is the escape (`configuration.md`'s checks section).
- **The single-root "one catch-all set" recommendation is incomplete** once a flow produces documents: the catch-all fires on a Markdown-only diff too (`configuration.md`, and `cookbook.md` wherever it shows a first `command_sets`).
- **The `--allowedTools` deny-direction fact is now written down for operators** — verified `claude` version, the two probes to repeat on a new major, and the sandbox-only fallback (the flow-authoring page's git-evidence section, mirroring the shipped `guide/flows/reference.md`).

## Runtime artifact retention + private-home footprint (2026-07-28)

Two layout/behavior changes and one new operator-facing page. `operations.md` currently **contradicts** the first two:

- **`worc logs clean` no longer stops at the subdirectories.** It sweeps the whole `.worc/logs/` root — per-task dirs _and_ the daemon logs (`daemon.log`, its rotated backups, `daemon-startup.log`) — keeping only the ledger unless `--all`, and `--keep N --all` now honors both flags instead of silently ignoring `--all`. It refuses while a task is active and holds the daemon logs back while a watch daemon is live (two distinct messages). `operations.md`'s "Cleaning up logs" section describes the old task-dirs-only behavior and the bare `(ledger kept)` output.
- **`daemon-startup.log` stops growing.** A console-spawned daemon drops its stderr handler once its `--log-file` is configured, so the startup log holds only pre-configuration output instead of duplicating the capped `daemon.log`. Anywhere the derived tree describes that file as the daemon's live stream, that is now wrong.
- **The four per-task roots moved under `.worc/runs/`.** `control-bundles/`, `instruction-bundles/`, `exchange-seals/`, `exchange-quarantine/` are now children of one `runs/` parent, and `runs/` — not the two bundle roots — is the named entry in the internal read-deny set (`worc_architecture.md`'s read-isolation description, `glossary.md` if it names the roots, `operations.md`'s `.worc/` layout). No migration code: the pre-rename directories are orphaned in existing targets.
- **New config key `logging.clean_runs_on_success` (default `true`), `schema_version` 31 → 32.** A successful task evicts its own `runs/` subtree; failed/parked tasks and quarantined evidence never are. `worc runs clean [--keep N] [--include-quarantine]` is the manual half (`configuration.md`'s `logging` block, `operations.md`'s command set).
- **`install --reconfigure` bounds its own backups** to the newest three of each `config.yaml.bak-*` / `flows.bak-*` / `tools.bak-*`; the operator's `state.db*.bak*` is never touched (`operations.md`).
- **A new shipped page, `guide/footprint.md`,** owns what the orchestrator leaves in the target repo. `operations.md` should point at it rather than re-deriving the table, and it is where the ledger's uncapped growth (~630 B per terminal task) is now stated for operators.

## Supervisor off switch + one deterministic PR body (2026-08-03)

The supervisor layer stops being unconditional, and the fallback summary stops being a stub.

- **New config key `supervisor.enabled` (default `true`), `schema_version` 33 → 34.** `false` removes all four phases (per-step observation, the whole-task finalize, the subtask handoff brief, the `skills.dynamic` node→skills proposal) — the layer object is simply never built. `configuration.md` needs the key plus two couplings resolved at load time: the rest of the `supervisor` block becomes inert and is no longer validated (one warning names it), and `memory.enabled: true` is forced to `false` for the run with a warning naming both keys, because that layer's closing turn is the only path that writes anything memory can later read back. `worc_architecture.md` describes the layer as constant — it is now constant **by default**; note also that "observes every completed step" was already stale after the cadence work. `operations.md` / `cookbook.md` want the "running without a supervisor" mode, and the fact that the flow-cadence narrowing rule is skipped when the layer is off (which is why turning it off is its own key rather than a global `observe.mode: none` — that global setting is refused for a flow declaring `events`, **after** the task is claimed).
- **`write_minimal_summary` is gone; one renderer writes the PR body on every terminal.** The four-field `What / How / Integration / Why` stub is deleted, and with it the `summary.json` triad `how`/`integration`/`why` — that file now has one key set everywhere: `{what, summary, [follow_ups], [supervisor_usage], [degraded]}`. Anywhere the derived tree documents the summary's shape (`configuration.md`, `operations.md`, `cookbook.md`), it now has sections Changes / Steps / Checks / Gates / Technical debt & follow-ups / Pipeline nodes skipped, is a pure function of `state.db` plus the task's artifacts (two renders are byte-identical), and never inlines the diff — it names the changed paths and points at `logs/<task-id>/current.diff`. A `failed` or `manual_action_required` run now gets a real report rather than a stub. `GitManager.diff_stat` was deleted with the stub (the stat comes from the durable `current.diff`).
- **Evaluator findings carry a persisted `gating` flag,** so only the findings a gate **let past** become PR follow-ups; a gating finding still open because a non-blocking evaluator spent its rework budget is kept, worded as still open. Wherever the follow-ups section is described (`configuration.md`, `cookbook.md`), that composition rule is new. `failure_report.json` findings gain the same additive key.

## Custom tool nodes must write UTF-8 on stdout (2026-08-04)

- **A `tool` node's stdout contract is now stated explicitly, because both shipped tools violated it on Windows.** `check_chapter` and `check_length` printed `ensure_ascii=False` JSON through the host's locale encoding; on a Windows host a piped child gets `cp1252`, which cannot encode the `≤` / `→` the violation messages carry, so the script died on its own `print` and the node reported a crashed checker instead of the `fail` it had computed. Both now pin stdin/stdout to UTF-8. Wherever the derived tree describes writing your own tool node (`configuration.md`'s tool-node section, `cookbook.md` if it shows one), the requirement belongs there too — the runner decodes stdout as UTF-8 on every OS, so a tool that falls back to the locale encoding is broken on Windows only. Mirrors the shipped `guide/flows/README.md`.

## Four critical defects from the P11/P12 post-mortem (2026-08-04)

Fixes for `analysis/02-critical-defects.md` C1–C4. No new config key, no schema-version bump.

- **A collapsed whole-task summary is no longer published.** Finalize prose below a low collapse floor (a one-liner or a probe; deliberately not "a real synthesis" length, because replacing honest short prose with a mechanical report is itself a regression, and it is a prose flow that would pay) is discarded, so `summary.md` is absent, the run is flagged `degraded`, and the deterministic report becomes the PR body (a WARNING carries the collapsed text). Wherever the derived tree says the fallback fires when the synthesis "could not run" (`operations.md`, `worc_architecture.md`'s summary description, `configuration.md`'s summary shape), it now also fires when the synthesis came back too short to be one. The `supervisor_final` audit row's `summary_written` now states what reached disk rather than what the turn returned. Every packaged finalize lens and the built-in fallback now state the expectation, so the contract is where the model reads it rather than only in the code.
- **`agents.providers.claude.allow_native_memory` is now the only switch governing the WRITE side of the native-memory deny.** `security.disable_read_isolation` lifts the read side only — the store stays `Write`/`Edit`-denied until the operator opts in, and the opt-in announces itself per run like `read-isolation: OFF` and `git-evidence: ON`. This is a real behavior change on the shipped default (previously that store had **no** deny rules at all and agents wrote into the operator's HOME). `configuration.md`'s security section and any threat-model text that lists what read-isolation-off relaxes both need the split; the `.worc`-is-the-complete-input-set claim in `worc_architecture.md` is true again.
- **The reused chain-PR body compacts in two passes.** Prose is elided first and the `## Technical debt / follow-ups` section is surrendered only if the body still exceeds GitHub's limit; the stub points at the task's committed `<id>.summary.md` — which rides the audit commit and is therefore in the PR's own diff — and falls back to naming the run host (`.worc/logs/<id>/summary.md`) for a run that committed none, instead of the old `logs/<id>/summary.md` that read as a repository path. An appended section now carries a second HTML comment recording that path, because the compactor runs later and over other tasks' sections. Anywhere `operations.md` or `cookbook.md` describes the chain-PR body being trimmed, follow-ups now survive that trim.
- **A follow-up record is triageable.** The evaluator's `fix` is persisted on the audit row and becomes the follow-up's `action_hint` (it was `null` on every mechanically derived record), and a derived `title` is the finding's first sentence with the remainder in `rationale` instead of a mid-word truncation of it. The persisted finding shape gains one additive key: `{severity, reason, paths, gating, fix}`. The finalize turn is also told not to restate the accepted findings that are merged in for it — worth stating wherever the follow-ups section's two sources are described.
