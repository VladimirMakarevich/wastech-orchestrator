# Code Audit — 2026-06-21

Findings gathered while reconstructing the functional specification (`docs/functional/`) **purely from the code** on 2026-06-21. Every item was verified against the implementation (the prior prose was not trusted). Scope = `src/wastech_orchestrator/`. Each finding: `file:line` · category · what's wrong · why it matters · suggested fix. Severity is a judgment call, not a label from the code.

Categories: **bug** · **robustness** · **security** · **dead/vestigial** · **dead-config** · **DRY** · **fragile** · **stale-comment** · **test**.

## High

1. **Resume crashes on a corrupt/missing normalized task artifact.** `robustness` — `core/orchestrator.py:727` (`_resume_task` calls `load_normalized` and `get_counters` **before** its `try/except` at `:742`) + `task/parser.py:231,237` (`load_normalized` does an unguarded `json.loads` + required-key access `data["id"]`/`data["title"]`). A corrupt/truncated `task.normalized.json` raises an uncaught exception out of `resume()` instead of degrading to `manual_action_required`/`failed`. **Fix:** move the pre-`try` reads inside the guard (or guard `load_normalized`) and fail closed to manual.
2. **`config.example.yaml` drops a security-relevant default denial.** `security` — `templates/config.example.yaml:71-74` `security.denied_commands` omits `gh pr merge`, but the loader default includes it (`config/loader.py:431`, asserted by `test_denied_commands_default_blocks_gh_pr_merge`). An operator who copies the example's `denied_commands` silently loses the merge denial. **Fix:** align the example with the loader default (and/or document that `denied_commands` replaces, not extends, the default).
3. **Custom `pr_title` is lost across a crash-resume.** `bug` — `task/parser.py:206` `write_normalized` omits `pr_title` from the manifest, so `load_normalized` restores it as `None` and a task resumed before `publish` falls back to `title` (`core/orchestrator.py:884` `pr_title=p.task.pr_title or p.task.title`). The sibling tri-state fields (`task_type`/`auto_merge`/`prompt_audit`) all have round-trip persistence + tests; `pr_title` has neither. **Fix:** persist `pr_title` in the normalized manifest.

## Medium

4. **Decorative flow `decomposition.gate` fields.** `dead-config` — `core/flow/schema.py:134-136` (`gate_min`/`gate_max`/`linear_depends_on`), parsed at `core/flow/snapshot.py:378-380` and set in `core/flow/packaged/implementation.yaml:89` (`gate: { min: 2, max: 8, linear_depends_on: true }`), are **never consumed**. `decide_decomposition` takes its bound from `config.agents.decomposition.max_subtasks` with a hardcoded floor of 2 and always enforces linearity. An operator setting `gate.max: 8` gets no effect. **Fix:** consume the flow gate, or remove the fields + YAML block.
5. **Decorative `commit_each_subtask` / `commit_per_subtask` / `min_size_signal`.** `dead-config` — flow `commit_each_subtask` (`core/flow/schema.py:137`, set in `implementation.yaml:91`) and config `commit_per_subtask` (`config/schema.py:125`) + `min_size_signal` (`config/schema.py:124`) are parsed but never read; subtask commit is unconditional (`core/orchestrator.py:1038`), and `templates/config.example.yaml:34-35` comments ("one local commit per subtask", "advisory threshold passed to the planning prompt") overstate them. **Fix:** wire them or drop them.
6. **Research/audit flows declare an unenforced global budget.** `dead-config` — `core/flow/packaged/deep_research.yaml:80` (`global_revision_iterations: 12`) and `security_audit.yaml:61` (`: 8`) are never read: the engine's global cap only looks up `global_fix_iterations` (`core/flow/run_state.py:37` `GLOBAL_FIX_KEY`, `engine.py:399`), so the cap silently falls back to `agents.max_total_fix_iterations`. The author's intended 12/8 ceiling does nothing. **Fix:** use the key `global_fix_iterations` in those flows (or make `_global_cap` read the flow's declared global key).
7. **Provider adapter duplication.** `DRY` — `providers/claude.py` and `providers/codex.py` (~600-700 lines each) carry parallel `run()` skeletons, request/redaction/preflight helpers, and a byte-identical tail (`_read_text`, `_redact_result_session`, `_parse_version`). Only argv-build, the error-signature table, and the parser genuinely differ. **Fix:** extract a shared base adapter / mixin.
8. **Evaluator "medium" severity is treated two ways.** `fragile` — `core/flow/nodes/evaluator.py:273-277` `_is_blocking` treats only high/critical/blocking as blocking (a `medium` finding does **not** drive `rework`), while `Finding.blocking` (`core/flow/engine.py:73`) reports `medium` as blocking. The carried finding and the routing decision disagree on `medium`. Also `_BLOCKING_SEVERITIES` and `_HIGH_SEVERITIES` (`evaluator.py:42,44`) are identical frozensets, and the `:43` comment says "medium/high" while the set omits medium. **Fix:** unify the blocking definition + drop the duplicate set.
9. **`partition_decomposition` can crash on a disconnected decomposition.** `robustness` — `core/flow/engine_driver.py:64-74` resolves the region entry/exit with `next(...)` and **no default**, but the validator (`core/flow/validator.py:251-259`) only checks that decomposition references resolve — not that `proposed_by` connects into the region or that the region has a forward exit. A structurally-valid but disconnected decomposition raises `StopIteration` instead of a clean `FlowValidationError`. **Fix:** validate region connectivity at load, or use `next(..., None)` → raise `FlowValidationError`.
10. **Supervisor's own session is not durable.** `bug` — `core/supervisor.py:76` `_own_session_id` is an in-memory instance attribute, never persisted to / hydrated from `node_lineage` (unlike the `resume_own_lineage` evaluator, `evaluator.py:208-231`), yet the docstring (`supervisor.py:17`) claims "durable across restart in P2.2". A resumed task constructs a fresh `Supervisor` and loses its accumulated cross-step context. **Fix:** persist the session via `node_lineage`, or correct the docstring.
11. **HITL cleanup misses `timeout` / `invalid_response` states.** `bug` — `core/hitl.py:399,420` (`reset_pending_interactions` / `consume_pending_interactions`) match only statuses `("waiting", "transport_error")`, but `write_answer` (`hitl.py:375`) also persists `"timeout"` / `"invalid_response"`. An interaction left in those states is skipped by cleanup; on `rerun --continue` the agent runner then hits the unresumable branch (`core/flow/nodes/agent.py:138`) and blocks at `manual_action_required` instead of asking fresh. **Fix:** match all failure statuses in the cleanup helpers.
12. **`detect_checks` duplicates B23 detection with a different algorithm.** `DRY` — `install/detect.py:135-163` re-detects ecosystems independently of the check resolver, emitting shell-string commands (first-match) vs B23's manifest/lockfile-aware argv lists. The same repo can get a different launchable check from the installer vs the resolver. **Fix:** have the installer seed the profile through the B23 resolver.
13. **`RedactionFilter` defense-in-depth gap.** `security` — `observability/logging.py:111,118,125` call `redact_text` with no `extra_secrets`, so the logging net catches only token shapes + `NAME=VALUE`, **not** literal denied-file values or raw session ids — while the docstring (`logging.py:103-105`) frames it as a catch-all for an accidentally-interpolated secret. The sibling prompt-audit path does pass them (`core/flow/observability.py:118,161`). **Fix:** thread a secret set into the filter, or tighten the docstring to the real (structural) coverage.
14. **PID-recycling window.** `robustness` — `process_control.py:50` writes only the bare PID; `is_running` (`:71`) probes via signal 0 with no start-time / boot-id (the docstring at `:75-77` acknowledges it). A recycled PID reads as alive, so `cmd_watch` may refuse a legitimate start or `stop_process` may signal an unrelated process. **Fix:** record the process start-time / boot-id alongside the PID and compare it.

## Transitional debt (note, not a single fix)

- **The `Stage` enum is a retained shim past its planned removal.** The code marks the `Stage`-enum removal + per-node audit paths as "land with P4" (`core/flow/wiring.py:56-58`), which has not happened. `build_stage_map`/`_stage_identity` (`wiring.py:47-79`) shoehorn arbitrary flow node ids into the 8-value enum with a heuristic capability default, collapsing same-identity nodes into one audit directory; the check-discovery request reuses `Stage.PLANNING` as a label (`checks/agent.py:99`). Removing `Stage` (per-node identities/audit dirs) is the intended cleanup.
- **Pervasive `§NN` spec-section anchors** in docstrings/comments across the codebase reference an external spec document that this functional reconstruction supersedes; they cannot be validated against the code and risk silent drift. Consider replacing them with links into `docs/functional/`.

## By design (recorded so they are not re-flagged)

- The fix-budget `min(flow_budget, config_cap)` clamp is intentional (config is the non-weakenable ceiling; a flow budget above the cap is the safe clamp case, `core/flow/validator.py:24-32`).
- A failed primary's partial diff is never auto-rolled-back — the fallback works from the current tree (`routing/snapshots.py`).
- `SESSION_UNAVAILABLE` consumes two `stage_attempts` (failed resume + fresh retry) by design — it is a same-provider safety net, not a free retry (`routing/router.py`).
- `dependency_scan` never gates (always `pass`) — gating is the flow's edges' job (`core/flow/checkers/dependency_scan.py`).
- The DB schema refusal for any non-zero older version is intentional greenfield fail-closed (`state_store.py:88-116`).
