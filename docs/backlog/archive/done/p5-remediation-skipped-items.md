## Resolved

- **A1-substantive (F42) — coverage-blocking demoted to advisory in the target `review.md`.** Done as a local edit to the gitignored operator copy `wastech-mdlint/.worc/flows/implementation/review.md` (a different repository, install-seeded and not version-controlled — the edit produces no commit). The blocking invariant "Missing test coverage … no unit test and/or no fixture test" was the driver of the 7-cycle rework loop on `p5-04`. It is now narrowed to a single blocking case — **zero** test coverage (no unit **and** no fixture) for **new core** user-visible behavior — while coverage _completeness_ (which kind, edge cases, both unit and fixture) moved to the advisory `## Test Coverage` section. Correctness/invariants stay blocking. The stale "extra-high" inline comment on the target's `review` node (`implementation.yaml`) was corrected to match the actual `reasoning: high`. Owner verify on the next large task: review on `high` + demoted coverage-blocking converges in ≤2 cycles without losing correctness findings.
- **D1-step 1 (F40) — task-authoring hygiene in the target repo.** Confirmed already remediated: no current target task combines `depends_on` with `branch_mode: existing` + a shared `branch_ref`; the p5-02..06 tasks serialize purely via the shared existing branch. The orchestrator also emits an **advisory warning** for the combination ([task/validation_gate.py](../../../../src/wastech_orchestrator/task/validation_gate.py)); the authoring rule itself stays a target-repo convention.
- **C2 — model/schema-400 error class (in-repo, shipped on `feat/p5-findings-remediation`).** A provider model/schema HTTP 400 previously fell through `classify` to `PROCESS_CRASHED`, which is fallback-eligible — so a 400 wastefully failed over to the other provider (which 400s the same request). New `ErrorClass.MODEL_REQUEST_INVALID` ([providers/base.py](../../../../src/wastech_orchestrator/providers/base.py)), a `\b400\b`/bad-request/invalid-schema/unsupported-parameter signature in **both** adapters ([providers/codex.py](../../../../src/wastech_orchestrator/providers/codex.py), [providers/claude.py](../../../../src/wastech_orchestrator/providers/claude.py)), and a secret-free `_MESSAGES` entry ([providers/errors.py](../../../../src/wastech_orchestrator/providers/errors.py)). It is in **none** of the fallback sets, so it fails loud (Core `_fail`), mirroring `INVALID_INVOCATION`. No `state.db` bump (free-text `error_class`). A new `test_every_error_class_has_a_message` exhaustiveness guard also surfaced and fixed a **latent** gap: `SESSION_UNAVAILABLE` had no `_MESSAGES` entry, so any session-not-found stderr would have `KeyError`ed in `classify`.
