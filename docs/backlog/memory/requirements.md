# Requirements

Status: **reviewed & locked for V1** — only tunable default integers remain (Q1 cleanup budget, Q5 packet caps). Date: 2026-06-29 — [task hub](index.md)

Requirements for the V1 build of the memory subsystem. Each item is tagged firm (decided) or **[refine]** (to be locked collaboratively — tracked in [questions.md](questions.md)). Rationale lives in [design.md](design.md) and [research/memory-architecture-blueprint.md](research/memory-architecture-blueprint.md).

## Functional requirements (FR)

- **FR1 — Persistent cross-task store.** Memory persists under `.worc/memory/` across independent runs on the same repo. It is **repo-scoped by location** (one `.worc/memory/` per working copy, alongside `state.db` / `flows/` / `config.yaml`) and is **local, gitignored orchestrator state** — task-independent, never committed, never in a PR, and **not shared across clones / machines / team members in V1** (a deliberate boundary tied to C1 no-secrets and C5 single-repo). **[firm]**
- **FR2 — Three tiers, all in V1.** Short-term episodic, long-term (semantic / procedural / reviewer / failure), and entity cards — all three are in V1 scope. They share the same seams (write at finalize, read as packets, one `MemoryService`) and land **staged** to isolate risk: (1) long-term lessons end-to-end first (proves the write→read→curate loop), (2) short-term episodic (cheap append + TTL), (3) entity cards last (most complex — needs `DerivedIndex` path/symbol existence checks for staleness, Q2). **[firm]**
- **FR3 — Write at task close (background, zero extra LLM).** Memory is written once per task at task close, through one deterministic funnel (`MemoryService`) fed by two sources: on **success** (publish) the supervisor emits a structured `candidate_memory_delta` in its **existing** finalize turn (no additional LLM call); on **terminal failure / manual** there is no supervisor turn, so a short-term **failure** record is built **deterministically** from the failure artifacts (no LLM at all) and is never promoted to long-term. The write is **best-effort** — it never blocks publish/close. **[firm]** (Verified against code: success rides `_engine_finalize` → `supervisor.finalize()`; failure/manual close via `_fail` / `_go_terminal` has no supervisor turn — see [design.md](design.md) §2/§9.)
- **FR4 — Read as per-node packets, node-driven by `{memory_path}`.** Memory reaches an agent only as a small, curated, per-node packet file passed by path — never the memory root. Which nodes get a packet is **fully node-driven and never hardcoded**: PacketBuilder builds one for **any** node whose (operator-editable) role prompt references `{memory_path}`, and skips the rest — so any node, including custom operator nodes, can opt into memory with no Core change. The packaged role prompts reference `{memory_path}` in `planning` / `implementation` / `review` / `fixing` by default, but that is editable configuration, not a Core constraint. A node with no relevant memory gets a minimal/empty packet, never a fabricated one. **[firm]**
- **FR5 — Deterministic management.** Validation, trust assignment, promotion, dedup, conflict handling, retrieval ranking, and cleanup are deterministic, inspectable, and **unit-testable without a model** (no fake-CLI). The model's **only** involvement in V1 is the success-path `candidate_memory_delta`, riding the supervisor's existing finalize turn; the failure-path delta and everything else are model-free. (The one future place a model/embedding could enter retrieval is the optional V3 semantic rerank — bounded, over the deterministic filter.) **[firm]**
- **FR6 — Curation surfaces.** Two triggers over one funnel (`MemoryService`), both audited and snapshotted: (a) an operator CLI **`worc memory show | validate | compact | restore`** — the on-demand **operator-control** path: `--dry-run` to preview, `compact` may run a **fuller pass** than the bounded idle job (the operator is in the foreground), `restore` to undo; read-only `show`/`validate` are always safe, while mutating `compact`/`restore` run when no task is active (atomic writes guard races); and (b) an automatic **bounded `CleanupJob`** in the `watch_loop` idle gap. Hand-editing the plain `md` / `jsonl` files is a first-class operator path (a `worc memory add/edit` for human-curated entries is a possible V1.x). External cron over the CLI is the operator's option, not a built feature. **[firm]** (idle-job cadence/budget: Q1).
- **FR7 — Global enable/disable switch.** A single switch in the **global `config.yaml`** (the `enabled` flag of the `MemoryConfig` block, e.g. `memory.enabled`) turns the entire subsystem on or off for the whole orchestrator. When disabled there are no `.worc/memory/` reads or writes, no `memory_path` injected into prompts, no `worc memory` side effects, and no background cleanup — behavior is exactly today's. It is a global switch (not a per-task toggle in V1). **Default:** an absent `memory` block (older/upgraded config) loads as **disabled** (no silent change on upgrade); `worc install` on a fresh project writes `enabled: true` (operator may decline). **[firm]** (full disabled-state guarantees: [questions.md](questions.md) Q10).
- **FR8 — Audit & rollback.** Every mutation (`append` / `promote` / `merge` / `quarantine` / `prune` / `restore`) writes one row to an append-only, **hash-chained** `audit/log.jsonl` (actor, source artifact ids, affected ids, pre/post content hashes, rationale), **and** a lightweight `evaluations` marker row mirrors it into the orchestrator's existing audited-decision trail (best-effort). **Batch** cleanups snapshot first; `worc memory restore` rolls back to a snapshot (snapshot-level in V1; per-entry undo handled via supersede/quarantine), so a bad write is cheap to undo. **[firm]** (exact `evaluations` row shape: phase 02 impl detail).

## Non-functional requirements (NFR)

- **NFR1 — Advisory only.** Memory shapes prompts; it never routes, gates, enforces, or acts — the Core still decides. Enforcement lives in deterministic orchestrator policies/hooks, never in memory text; agent-generated procedural memory stays advisory until a human promotes it into `AGENTS.md` / a role prompt / a skill (no stealth control plane). **[firm — invariant]**
- **NFR2 — Source of truth is code + artifacts + checks.** Memory is distilled, **provenanced** knowledge _about_ them, never a replacement. On any conflict with current code / docs / checks, the live repo wins and the memory entry is revalidated → stale/quarantine — never the reverse. Durable entries without an evidence pointer do not persist. **[firm — invariant]**
- **NFR3 — Memory ≠ derived index.** Repo map / symbol index / code search are a separate, **rebuildable cache** plane (deletable and recomputable from the current tree, no audit/snapshots) — distinct from durable, audited memory. Memory never stores what the index can recompute. In V1 `DerivedIndex` is minimal (path/symbol existence for staleness, Q2); a richer index is a separate concern. **[firm]**
- **NFR4 — Precision-first & bounded.** Retrieval is metadata-first; each packet is hard-capped by **per-node, configurable** limits (`MemoryConfig`) expressed primarily as **item counts** (long-term / entity / episodic) with a char/line backstop — not a token-exact cap. Over cap, PacketBuilder drops whole lowest-ranked records (never partial), keeping packets coherent. Approach is **[firm]**; default integers are set (Q5) and tunable.
- **NFR5 — Safety from day one.** Mandatory redaction before every write — V1 reuses the existing `redact_text` / `redact_mapping` (pattern-based, same path as HITL/artifacts; a dedicated verification scanner is possible later, not V1) — plus deny-by-default allowlisted storage, trust levels + provenance enforced through write→retrieve→act, quarantine, append-only hash-chained audit, snapshots, and rollback (detail in design §7 / FR8). **[firm]**
- **NFR6 — Bounded autonomy.** Background cleanup runs **only when no task is active**, fail-closed, no network, never creates long-term lessons, never edits code/docs/skills. Cadence is **opportunistic + work-gated**: in the idle gap a cheap "is there work?" check gates one bounded pass, rate-limited by a configurable `min_interval`. Per-pass budget is a set of `MemoryConfig` knobs — `max_scanned`, `max_edits`, `max_wall_clock`, `promotions_per_pass = 0`. Constraints + approach **[firm]**; default integers are set (Q1) and tunable.
- **NFR7 — Provider-neutral.** The canonical store is our own neutral `md` / `json` / `jsonl`. The only thing a provider ever sees is the rendered per-node packet file (identical regardless of provider); we never read provider-native memory (Claude auto-memory, Codex memories) as the source and never write into it. **[firm]**
- **NFR8 — Cross-platform.** Windows / Linux / macOS. `pathlib` + `Path.as_posix()` for every stored/compared path string (records round-trip identically). All memory files written **UTF-8 with explicit `\n`** so content hashes are stable across platforms — the audit hash-chain and `restore` depend on it. The idle/cleanup control uses the self-managed PID/stop-file, never `os.kill`/`signal`. **[firm — invariant]**
- **NFR9 — No added LLM cost / hot-path latency.** Memory adds **zero** LLM calls beyond the supervisor's existing finalize turn it rides (FR3/FR5), and only bounded, deterministic I/O to any node's hot path (packet build) — negligible added latency. Cleanup is model-free (NFR6). This NFR is the consolidated cost guarantee; FR3 / FR5 / NFR6 are the mechanisms. **[firm]**

## Constraints (hard invariants — must not be violated)

- **C1 — No secrets** in memory, logs, `state.db`, or artifacts — even though memory is gitignored, because agents read it back into prompts whose outputs land in committed artifacts. Enforced by NFR5 (redaction **before** write closes the re-surfacing path).
- **C2 — Not in `state.db`.** Memory must not live in the state-machine store (it would couple memory to the state schema and make it un-hand-editable). Memory carries its own versioning in `manifest.json`, independent of `state.db`. If a structured store is ever needed it is a separate `.worc/memory/memory.sqlite` (V2, with `json`/`jsonl` retained for inspection) — never a `state.db` schema bump.
- **C3 — Not an unbounded context dump.** Memory stays small and curated; raw transcripts / whole vendor sessions / full diffs / large logs are forbidden (full don't-store list: design §4 / blueprint §5.2). Boundedness is enforced by NFR4 (packet caps) on read and FR6 cleanup on the store.
- **C4 — Supervisor stays advisory (narrow).** It distills — emits a candidate delta on success — and nothing more: no promotion authority, packet assembly, cleanup ownership, or policy enforcement. Those belong to the deterministic `MemoryService` / `PacketBuilder` / `CleanupJob` (NFR1, design §1, [role-split note](research/supervisor-role-split.md)).
- **C5 — Single repo, single active task (V1).** Cross-repo memory, shared/committed memory, and concurrent-task memory access are out of scope while the orchestrator's single-repo / single-active-task invariants hold (`acquire_slot`); revisited if worktree concurrency lands. See [out-of-scope.md](out-of-scope.md).

These extend, never override, the repo invariants in [../../../CLAUDE.md](../../../CLAUDE.md), [../../../AGENTS.md](../../../AGENTS.md), and [../../../.agents/rules/](../../../.agents/rules/).
