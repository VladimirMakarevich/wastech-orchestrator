Часть P2 ([p2-implementation.md](p2-implementation.md)). Ландит последним в P2, после [P2.4](p2.4-hybrid-testing.md).

> **Правка решения (2026-06-19).** Опциональный `testing_quality`-узел в дефолтный packaged-флоу **не добавлен**: опциональность узла обеспечивается формой графа (узел есть/нет во флоу-YAML), а не глобальным конфиг-флагом. Завязка `agents.hybrid_testing` + `when: config.hybrid_testing` + ветка в `_engine_facts` («прибивание к оркестратору») убрана. `test_quality`-evaluator остаётся generic-возможностью рантайма (P2.4); оператор включает его, вписав узел в свой флоу. Дефолтный packaged-граф остаётся 7-узловым. Reference-форма с `testing_quality` — в [co-design/implementation.yaml](co-design/implementation.yaml).
>
> **Контекст перед реализацией (2026-06-19, исходный план до правки).** P2.5 вырастает packaged `implementation.yaml` до целевого графа (опциональный `testing_quality`-узел + mutation guard на `checks`) и добавляет оставшиеся spec-тесты + тест minimal-flow.

Полный граф исполняется данными; тесты из спек трёх программ зелены. Целевой граф ([flow-contract.md](flow-contract.md) §7): refinement → planning → implementation → testing(`checks`) → review(evaluator) → fixing → publish, с двумя fix-петлями (`test_fix`, `review_fix`), опциональным `testing_quality`-узлом и decomposition. **`supervise_impl`/`supervise_fix` и summary-узел в графе отсутствуют** — supervisor (summary + advisory) делает константный слой оркестратора перед `publish` (P2.1).

## Touchpoints

- Packaged [implementation.yaml](../../../src/wastech_orchestrator/core/flow/packaged/implementation.yaml) — P2.5 наращивает P1-parity форму до целевого графа: добавляет опциональный `testing_quality`-узел и mutation-guard-свойство `checks`; **не** добавляет supervisor-узлы (их роль ушла в константный слой).
- Константный supervisor-проход оркестратора (P2.1) встраивается в финал любого flow перед `publish`.
- Тест-сьют объединяет durable + hybrid + review spec-тесты на одном flow + supervisor-слой поверх.
