| [Rerun dead-end: fails before its first checkpoint on an operator-owned branch](rerun-dead-end-pre-checkpoint-existing-branch.md) | A task that fails at flow resolution (e.g. flows edited while the daemon was serving the queue) on a `branch_mode: existing`/`current` branch can be re-attempted by **neither** `rerun` mode: fresh refuses (won't reset an operator-owned branch), `--continue` refuses (no checkpoint was recorded — it died before any node). `--from` can't rescue it (continue-only + needs a checkpoint). Only workaround today is re-queuing the file (`worc run <failed-file>` / shell `enqueue`+`up`), which bypasses `rerun` and loses the ledger attempt-history. Proposes making `rerun` restart in place on the existing branch for the no-checkpoint case (Option A), plus resolving the flow pre-slot so the dead-end can't form (Option C). | From a live `wastech-mdlint` run (`p7-03-graph-tools`); sibling of the shipped [rerun-flow-drift-and-budget-confirm.md](rerun-flow-drift-and-budget-confirm.md), which only covered tasks that _had_ a checkpoint. `state.db` stays sole authoritative state; branch-ownership invariant unchanged. |
| [Rerun flow-drift reconciliation and fix-budget confirmation](rerun-flow-drift-and-budget-confirm.md) | **Implemented 2026-07-12** (simplified from the original proposal — see the ADR's top note). `rerun --continue --from NODE` used to refuse on any whole-file flow-fingerprint drift, even changes upstream of `NODE`; `--from` now resumes through any drift as long as `NODE` exists (no structural compatibility check, no new flag), rebaselining the checkpoint's fingerprint so the resume actually lands at `NODE`. Plus an interactive confirmation gate, scoped to the whole forward-reachable path, before resuming into an already-exhausted fix-loop budget. | Closes the deferred flow-fingerprint-drift item named in [follow_ups.md](follow_ups.md) (from the now-removed `universal-resume-recovery.md`); `state.db` stays the sole authoritative state, no manual SQL edits. |
