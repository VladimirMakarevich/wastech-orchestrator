# Backlog

Status: **inventory** Date: 2026-06-21 Owner: Vladimir Makarevich

This folder is the single place for backlog and deferred-product ideas for **wastech-orchestrator**. It is an inventory, not an implementation contract. The source of truth remains the code.

Backlog documents must not override the hard invariants from [../../CLAUDE.md](../../CLAUDE.md), [../../AGENTS.md](../../AGENTS.md), or [../../.agents/rules/](../../.agents/rules/).

Where to find the design detail:

- **Open items** keep their detailed design in a file in this folder, linked from the tables below.
- **Implemented or closed items are deleted from this folder.** Once an item lands, the code, its tests and the commit history are its record; a design document left beside them goes stale and starts contradicting the thing it describes, so it goes rather than moves.
- **Build-time tech-debt and implementation follow-ups** are not tracked in this folder — raise them in the change that discovers them.

| [Full tool access for agents — deny-only instead of an allow-list](full-tool-access/README.md) | **Written in Russian** (operator-authored goal, unchanged; revised 2026-08-05 after review). Maps the four walls a command passes — Claude's `--tools` existence gate, the OS-dependent env allowlist (9 names on POSIX, 19 on Windows), the OS sandbox (write only in the clone + temp), and the network policy — plus the **fifth door already open**: `checks.command_sets` runs the operator's `dotnet test` with no sandbox at all, so steps 2–3 buy the _agent_ an in-turn build loop, not "building the project". Records what dropping `--tools` does and does not do: it inverts the existence gate for Claude's **built-in tools** (which the goal asks for), but the utilities themselves are unlocked by one thing only — `Bash` existing on a `read-only` profile; on `workspace-write` the command space is already deny-only. Steps: **0a** the corrected cross-platform `allowed_environment` (the POSIX-only list would drop Windows' `SystemRoot` and crash `claude.exe`), **0b** `security.extra_environment` (sets toolchain values; scope is _every_ child process, Check Runner included) with caches redirected into a gitignored dir in the clone, **0c** prefix patterns (`DOTNET_*`, `npm_config_*`) filtered through the existing `is_sensitive_key` so the next toolchain needs no up-front inventory of its variable names (adding a plain name needs no code change either — the saving is not having to know the zoo); **1** `read-only` nodes get a shell + `allow_unsandboxed_shell` for hosts with no sandbox; **1b** retire `git_evidence` (behind `upgrade-flows`); **2** `extra_writable_paths`; **3** `allowed_domains` (default `["*"]`) + a Codex network opt-in; **4** `unsandboxed_commands`. Ends with a **Принятые ослабления** ledger — eleven named relaxations, each with its key, its default, and what stops holding the line — plus **Решения владельца по итогам аудита** (all six closed) and a **Живые пробы** evidence table. | Owner decision 2026-08-05: the goal wins, security may be lowered where it blocks the goal — each relaxation gets its own key (default = today's behavior) and a loud preflight line. Two corrections that change the design: the OS sandbox wraps **only `Bash`** — Claude's built-in `Write`/`Edit` bypass it ([`claude.py:749`](../../src/wastech_orchestrator/providers/claude.py)), so for built-in tools and for all of Windows the deny **pattern is the boundary**, not the belt; and dropping `--tools` removes the only mechanism that strips `Bash` on native Windows, so without an explicit bare-name `Bash`/`PowerShell` deny step 1 silently ships an unsandboxed shell. Re-audited 2026-08-05 against the code and live `codex-cli 0.144.4` / `claude 2.1.222` probes, which overturned four mechanism claims: Codex `network.domains` is a **table**, not a list (the list form does not parse), an unknown profile key parses **silently** (so a renamed key yields no policy and no diagnostic), `gh`/`osascript -e` **work inside** the sandbox — so step 4 must not except `gh`, which would hand back a publication path for free — and the built-in tool inventory is **not enumerable** from the CLI while unknown tool names are **not validated**, so the "canary against the CLI's tool set" that step 1's fail-open model rests on has no mechanism. Also found: with a clone under the global `/private/tmp`, `:workspace`'s inherited temp grant **defeats** the explicit `deny` carve-outs (holds under `$HOME` and `$TMPDIR`), and `repo.local_path` is unconstrained. Post-audit owner decisions: `--tools` is not emitted at all (the `--tools default` variant, which would have kept the flag-drift preflight probe, was rejected); the fail-open deny model ships **with no replacement insurance** (its own ledger row — the most expensive relaxation here); `extra_writable_paths` applies to every shell-bearing attempt, `read-only` included; a temp-rooted clone gets a loud preflight line rather than a validator ban; control-state drift on a `read-only` node stays **`warn` only, fleet-wide — nothing parks** (so on the shipped default, `telegram.trace: false`, the sole trace of a real isolation failure is one log line — which makes that trace part of the mitigation, not a nicety); and `gcloud`/`terraform` stay in step 4 as explicitly **unprobed candidates**, never to be written into the key without their own probe. Ordering is a correctness constraint on four counts: `write_guard` for **every** attempt, re-keying the violation-detection bracket from the `git_evidence` grant to "has a shell" (else step 1 mutes the only signal that isolation failed), the platform branch, and 1b after `upgrade-flows` (flows parse fail-closed, so deleting the key breaks every installed `deep_research`). Pulls in both halves of [read-only-shell-residues.md](read-only-shell-residues.md) as co-requisites — step 1 voids their deferral rationale. Step 1 is the highest-risk step, not a cheap one. **Status 2026-08-13: step 0 is accepted and split into four phases** — the folder is now a campaign ([full-tool-access/](full-tool-access/README.md)) whose `requirements-step-0.md` is the acceptance contract; steps 1, 1b, 2, 3 and 4 stay proposed and are opened one at a time. Recorded alongside them as an explicit **open question, not accepted**: an "advanced mode" — one switch for total freedom over the environment, `extra_environment` and the tool set, on the operator's own responsibility — deliberately queued **after** step 0, since step 0 is what measures how much configuring is actually left. |
