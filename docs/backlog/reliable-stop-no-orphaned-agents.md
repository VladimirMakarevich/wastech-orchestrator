# Reliable stop: no orphaned agents on any stop route

Status: **proposed** (2026-07-04) Date: 2026-07-04 Owner: Vladimir Makarevich

Make "stop actually stops, and nothing is ever orphaned" true for **every** way an operator ends a run — Ctrl-C, `worc stop` (soft), `worc stop --force-full`, a `run_process` timeout, and the daemon's own exit — not only the `--force-full` rung it is true for today. The orchestrator records a handle on the active agent `(pid, pgid, start_time)` and owns a single "kill the whole agent subtree" primitive (group-kill plus a recursive descendant sweep as backstop) that every stop route calls. Discovered during a real `worc watch` test on macOS where the operator could not stop an in-flight implementation agent by any means short of rebooting the machine — the exact "confirm Ctrl-C stops the agent (no orphan)" validation that the R1 hard-stop remediation ([cli-upgrade-remediation.md](archive/done/cli-upgrade-remediation.md) Phase R1) shipped but never ran for real.

## The problem

The "no orphan" guarantee lives on a single rung. R1 fixed the process-group topology so that `stop --force-full` → `killpg(getpgid(daemon_pid), SIGKILL)` reaches the agent (the agent no longer `setsid`s away; the daemon leads its group; the agent inherits it — [process.py:100-105](../../src/wastech_orchestrator/providers/process.py#L100-L105), [process_control.py:385-428](../../src/wastech_orchestrator/process_control.py#L385-L428)). But that is the _only_ route that group-kills. Every other way to end a run targets a single PID and orphans the agent's descendant subtree:

- **Soft `worc stop` is honored only between ticks and is never forwarded to the agent.** While an agent runs, the daemon is blocked inside `subprocess.run`; the SIGTERM handler merely sets a `threading.Event` the loop polls between ticks ([process_control.py:574-575](../../src/wastech_orchestrator/process_control.py#L574-L575), [cli.py:1199-1227](../../src/wastech_orchestrator/cli.py#L1199-L1227)). The stage runs to completion before the event is seen, and SIGTERM is never sent to the agent — so a soft stop is inert against an in-flight agent.
- **The one working option is hidden.** A bare `worc stop` on a busy task in a TTY routes to `_confirm_yes`, where a typed `YES` maps to **soft only** ([cli.py:2150-2153](../../src/wastech_orchestrator/cli.py#L2150-L2153), [cli.py:1281-1290](../../src/wastech_orchestrator/cli.py#L1281-L1290)); the prompt never mentions `--force`/`--force-full`. Field observation: the operator ran only bare `stop` (never `--force`/`--force-full`) and confirmed `YES`, so the instinctive command deterministically selected the one mode that cannot interrupt a running agent.
- **Ctrl-C kills only the direct child.** On `KeyboardInterrupt`, `subprocess.run` calls `process.kill()` on the agent PID alone, then re-raises; `cmd_watch`'s `finally` only unlinks the PID/stop files ([cli.py:2114-2119](../../src/wastech_orchestrator/cli.py#L2114-L2119)). The daemon exits while the agent's own children — tool subprocesses, MCP servers, a spawned shell — survive as orphans.
- **`run_process`'s timeout has the same single-PID kill.** `subprocess.run(timeout=…)` → `TimeoutExpired` → `process.kill()` on the direct child only ([process.py:88-111](../../src/wastech_orchestrator/providers/process.py#L88-L111)). Even absent operator action, a timed-out agent orphans its descendants.
- **Group-kill is not a containment boundary.** A modern coding-agent CLI can spawn descendants into their own session/process group. `killpg(daemon_group)` does not reach a broken-away group, and the orchestrator **records the agent PID nowhere** ([process_control.py](../../src/wastech_orchestrator/process_control.py) has no child handle), so `stop` from another shell has no fallback. R1 fixed the agent's _own_ group membership but assumed its subtree stays in-group — the field disproved that.

Net effect reproduced on macOS: Ctrl-C returned the terminal but a descendant kept mutating the git working tree (reverted files reappeared because a live process kept rewriting them); soft `worc stop` did nothing; `kill -9` on the two visible PIDs left a broken-away grandchild running; clearing memory/logs was irrelevant (state, not process); only a reboot ended it.

## Constraints

- **`process_control.py` stays subprocess-free.** Its no-shell-out design must hold: the recursive descendant sweep and any `taskkill` live in `providers/process.py` (where `hard_kill_tree` already does) and reach `process_control.stop_process` as an **injected seam**, exactly as R1 wired `hard_kill_fn`.
- **Launch/kill without shell interpolation.** Every spawn and kill is an argv list with `shell=False`; the descendant walk must not build shell strings from PIDs or paths.
- **Cross-platform is mandatory.** The subtree-kill branches per OS — POSIX `killpg` + descendant walk (`/proc` on Linux, `pgrep -P`/`ps -o pid,ppid` on macOS), Windows `taskkill /F /T` — and each branch is tested; no `os.kill`/`signal` assumptions on Windows.
- **No secrets in the child-handle file.** The `(pid, pgid, start_time)` handle written under the runtime root carries no argv, env, prompt, or path content — the same discipline as the PID file.
- **The core does not learn CLI syntax; providers do not commit/push/PR.** This change touches only process lifecycle (launch/observe/kill) and the CLI stop surface; it adds no provider-specific logic to the core and no publish behavior to providers.

## Alternatives considered

| Option | Why not chosen |
| --- | --- |
| Do nothing (`--force-full` is the documented hard stop) | The rung exists but is undiscoverable and porous: operators reach for bare `stop`/Ctrl-C, and even `--force-full` misses broken-away descendants. This is the state that forced a reboot. |
| Minimal: daemon-exit `finally` hook that kills the recorded agent + surface `--force-full` in the prompt | Fixes the daemon-exit orphan and discoverability, but still relies on group membership — a descendant that broke into its own session survives (RC-C unaddressed). A half-measure. |
| Keep the agent in the daemon's group (R1 topology) + add a descendant sweep | Fewer changes to R1, but keeps daemon and agent SIGINT coupled and offers no clean fast path independent of the daemon's group; the recorded-handle approach is strictly cleaner. |
| Real OS containment now (cgroup v2 / PID namespace on Linux, Job Object on Windows, or a container runtime) | The only fully hermetic answer to "the CLI spawned something we cannot see," but a large, platform-specific build. Recorded-handle + subtree-kill removes the operational pain at a fraction of the cost; containment is recorded as the north star, not this ADR. |
| Make soft stop cooperatively cancel a running agent mid-stage | Rejected for this ADR: soft keeps its "let the current step finish" contract; interrupting _now_ is `--force-full`'s job, which we make discoverable instead. |

## Decision

We give each agent its **own** session/process group again (`setsid`, reverting that part of R1) and have the orchestrator **record its `(pid, pgid, start_time)`** to a dedicated child-handle file (`<runtime-root>/orchestrator.children`, written atomically via temp-file + rename like the PID file) at spawn time, cleared on return. R1's goal — a hard stop that orphans nothing — is then met through the _recorded handle_, not through shared group membership. A single primitive, `kill_agent_subtree`, does `killpg(agent_pgid, SIGKILL)` as the fast path **plus** a recursive descendant sweep as a backstop for anything that escaped the group (POSIX walk via `/proc`/`pgrep`; Windows `taskkill /F /T`). Every stop route calls this primitive: `--force-full`, the `run_process` timeout, and — closing the main orphan mechanism — the daemon's own `finally`/shutdown path, so Ctrl-C or a daemon crash reaps the whole agent subtree before the PID file is removed. Soft stop keeps its between-ticks "finish the current step" semantics, but the interactive prompt and the busy-refusal now name `--force-full` explicitly, so the only command that interrupts _now_ is discoverable.

The cost of the rejected paths: "do nothing" and the minimal hook leave a control surface that orphans work under normal operator instincts; full OS containment is the right end state but far more build than the incident warrants today.

## Resolved decisions (2026-07-04)

- **Handle storage — a dedicated, atomically-written file.** The active agent's `(pid, pgid, start_time)` goes to `<runtime-root>/orchestrator.children`, written temp-file + rename and reaped on the agent's return, symmetric to the existing `orchestrator.pid`. Not a `state.db` column: a schema bump for two integers would add coupling and pull DB access into the stop path, which already reads only files (PID / stop-file).
- **Recycling guard — pid/pgid-only off Linux, accepted.** `start_time` tightens the PID-recycling guard only on Linux (`/proc`); on macOS/Windows the handle degrades to a bare pid/pgid probe. Accepted as-is: the kill fires within seconds of writing the handle (at stop time, not an hour later) and targets the agent's **process group**, not a lone PID, so the recycling window is negligible. A macOS `ps -o lstart=` start-time stays the deferred tightening it already is for the daemon PID guard.
- **A stop-killed agent must be flagged as a cancellation so the Router never falls back to a fresh agent (traced 2026-07-04).** A SIGKILLed agent is `launch_error=None, timed_out=False, exit_code≠0`, so it skips the launch/timeout branch, fails to parse the truncated stream, and classifies as `PROCESS_CRASHED` ([_adapter_base.py:361-373](../../src/wastech_orchestrator/providers/_adapter_base.py#L361-L373)) — which **is `FALLBACK_ELIGIBLE`** ([base.py:48-60](../../src/wastech_orchestrator/providers/base.py#L48-L60)). So if the agent dies while the daemon's Router loop is still runnable, the Router immediately launches the **fallback provider's** agent ([router.py:371-400](../../src/wastech_orchestrator/routing/router.py#L371-L400)) — a fresh process. After the Router exhausts, `PROCESS_CRASHED` is not in `TRANSIENT_RETRYABLE`, so the orchestrator `_fail`s the task (terminal, **not** `_park`/resumable — [orchestrator.py:1729-1736](../../src/wastech_orchestrator/core/orchestrator.py#L1729-L1736)); a `FAILED` task is not auto-resumed on the next tick, so there is no cross-tick respawn. The three chosen stop paths are all safe by construction — Ctrl-C raises `KeyboardInterrupt`, which bypasses the Router's `except ProviderError` (no fallback); `--force-full` `killpg`-SIGKILLs the daemon and agent together (the daemon can't run the fallback); soft never kills the agent. **The requirement this produces:** a stop-initiated kill must be distinguishable from a genuine crash (a cancellation sentinel checked before fallback), so no future in-stage-cancel path — or a signal-delivery race — can turn a stop into a fallback respawn or a spurious `_fail` report.

## Validation

- **POSIX is the acceptance gate for this ADR; Windows is a tracked "validation pending" follow-up.** Automated POSIX-gated real-topology tests plus a manual macOS/Linux smoke (start a daemon, run a task, then (a) Ctrl-C and (b) `stop --force-full`; confirm the daemon **and** the full agent subtree die with no survivor, and `resume()` recovers on next start) close the fix on POSIX. The real Windows smoke — the step R1 never completed — becomes its own follow-up on implementation; the hard stop is **not** prod-trusted on Windows until the owner runs it. This ADR supersedes the R1 Ctrl-C validation follow-up (2026-07-02) and folds it into this gate.

## Implementation notes

Primary seams, all under `src/wastech_orchestrator/`:

- [providers/process.py](../../src/wastech_orchestrator/providers/process.py) — `run_process`: switch from `subprocess.run` to an explicit `Popen` so the child's `pid`/`pgid` can be recorded via an `on_spawn` seam the instant it launches and cleared on return; re-add `start_new_session=True` for the agent (its own group). Add `kill_agent_subtree(pid, pgid)` = `killpg` + recursive descendant walk (POSIX) / `taskkill /F /T` (Windows), reusing the `hard_kill_tree` pattern.
- [process_control.py](../../src/wastech_orchestrator/process_control.py) — accept the subtree-killer as an injected seam (as with `hard_kill_fn`); read/write the child-handle file (no subprocess in this module); have the `level="full"` branch target the recorded agent handle, not `getpgid(daemon_pid)`.
- [cli.py](../../src/wastech_orchestrator/cli.py) — `cmd_watch`: in `finally` (and the `KeyboardInterrupt` branch), call the subtree-kill on the recorded active agent before unlinking the PID file. `_resolve_stop_level`/`_confirm_yes`: surface `--force-full` in the interactive prompt and the non-interactive refusal. Wire the default subtree-killer seam through `_gated_stop`.
- Tests: a POSIX-gated real-topology test where a parent spawns a group-leader child that spawns a grandchild in its _own_ group; assert every route (daemon-exit hook, timeout, `--force-full`) reaps the grandchild too; Windows path via the injected-seam pattern R1 already uses.
