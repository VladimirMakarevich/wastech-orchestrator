# Решение владельца: в advanced mode ОС-песочница Claude выключается

Status: **решение принято, реализация не начата** Date: 2026-09-03 Owner: Vladimir Makarevich

Документ фиксирует одно решение и его цену. Доказательная база — инвестигейт [advanced-mode-sandbox-scope.md](../advanced-mode-sandbox-scope.md), который нашёл причину F7; здесь только то, что из неё следует для кампании.

## Что решено

**Под `strict_isolation: false` агент не ограничивается ничем, и ОС-песочница Claude входит в это «ничем».** На macOS и Linux она в режиме больше не поднимается — так же, как сегодня на нативной Windows и на Linux без `bwrap`+`socat`. Под `strict_isolation: true` не меняется ничего.

Решение принято владельцем на формулировке «под `strict_isolation: false` у агентов не должно быть никаких ограничений» и подтверждено измерением, а не только волей: см. следующий раздел.

## Почему не ключом и не Шагом 4

Инвестигейт закрыл обе альтернативы, каждую своим фактом.

**Ключа не существует.** Отказ F7 сидит на **пятой оси** — System V IPC (`ipc-sysv-sem`), которую seatbelt-профиль Claude не разрешает вовсе. Настроечная поверхность песочницы у CLI исчерпывается списком `sandbox.enabled`, `failIfUnavailable`, `allowUnsandboxedCommands`, `excludedCommands`, `autoAllowBashIfSandboxed`, `filesystem.*`, `network.*`, `credentials.*`, `seccomp.bpfPath`, `workspace` — **ни один ключ до этой оси не достаёт**. Аналога `allow_write_root`, которым вылечили `~/.nuget` на стене 3, здесь нет и быть не может: профиль вендорский, внутренние опции его сборщика (`enableWeakerNetworkIsolation`, `allowMachLookup`, `allowPty`) оператору не выставляются.

**Перечислить класс нельзя.** Сегодня на этой оси `lmdb-js`, а через него — персистентный кэш Angular CLI, то есть любой Angular/Ionic-билд с настройками по умолчанию. Но профиль меняется с версией CLI, и какой тулчейн сломается следующим, мы не узнаем до прогона. Это и есть аргумент против точечных заплаток: чинить придётся не отказ, а ось.

**Шаг 4 не годится.** `unsandboxed_commands` был «единственным существующим рычагом» ровно пока считалось, что песочница остаётся. Она не остаётся — и тогда Шаг 4 не даёт ничего, чего не даёт выключение, а стоит собственной дыры: тело `npm run build` живёт в `package.json`, который агенту доступен на запись, поэтому список по имени команды означает произвольное исполнение вне песочницы. **Шаг 4 закрывается как ненужный**, а не как отложенный.

## Механика реализации

1. **Одна ветка в `_resolve_tool_plan`** ([`claude.py:412`](../../../src/wastech_orchestrator/providers/claude.py)): `needs_sandbox = True` только под `strict_isolation`. Отказ для `LINUX_MISSING_DEPS` уже висит под тем же флагом и не трогается.
2. **Файл настроек в режиме всё равно пишется — с явным `sandbox.enabled: false`.** Это поправка к «просто не эмитить `--settings`»: без нашего файла шелл сегодня и правда несендбоксенный (проверено пробой), но это вендорский дефолт плюс `--setting-sources project`, то есть состояние, которым управляют чужой репозиторий и следующая версия CLI. Тот же аргумент, по которому `autoAllowBashIfSandboxed` уже пишется явно, а не наследуется ([`claude.py:738-742`](../../../src/wastech_orchestrator/providers/claude.py)).
3. **Убрать то, что становится мёртвым:** `allow_write_root` и `_write_anywhere_root` ([`claude.py:754-782`](../../../src/wastech_orchestrator/providers/claude.py), [`claude.py:1846`](../../../src/wastech_orchestrator/providers/claude.py)) существовали только как обход песочницы. `build_sandbox_settings` остаётся как есть для strict-режима.
4. **Громкая строка.** `host_floor_gap` ([`claude.py:1078`](../../../src/wastech_orchestrator/providers/claude.py)) сегодня profile-blind и смотрит только на возможности хоста; ему нужен `strict_isolation`, чтобы `worc preflight` ([`cli.py:3547`](../../../src/wastech_orchestrator/cli.py)) и лог прогона ([`orchestrator.py:2739`](../../../src/wastech_orchestrator/core/orchestrator.py)) печатали `isolation-floor: NONE` на **любом** хосте под режимом. Расширение сигнатуры — осознанная правка контракта: функция была намеренно config-blind.
5. **Тесты:** `needs_sandbox` на macOS/Linux при обоих значениях флага; `sandbox.enabled: false` в сгенерированном файле; редакторские denies на месте без песочницы; `host_floor_gap` даёт причину в режиме на всех четырёх capability.

Одно проверить живьём до смены дефолта: без песочницы `autoAllowBashIfSandboxed` ничего не значит, и авто-одобрение `Bash` в headless-прогоне держится только на `--allowedTools`, куда `Bash` в режиме и так попадает.

## Что теряется — честно

Ровно одно: **подпроцессы, которые агент запускает из шелла, перестают быть связаны ОС.** `git`, `rm`, скрипт из `package.json` — механически больше не остановлены на `.git` и `.worc`. Из ТA.1.1 («`.git` неписабелен любым путём… оба механизма обязательны») отпадает механическая половина для подпроцессов; вторая половина — редакторские denies — держится, потому что встроенные инструменты песочницу и так не проходят.

Это **не новая цена, а распространение уже принятой**: на нативной Windows и на Linux без зависимостей режим сегодня отдаёт несендбоксенный шелл, и там гарантия уже заменена на advisory-контракт в промпте плюс детект постфактум. Требование к форме остаётся прежним: отпадает **вслух**, громкой строкой, а не молча.

## Что не меняется

- **Публикацию оркестратор агенту не делегирует.** Ни один узел не получает мандата на commit/push/PR.
- **Редакторские denies** (`Write`/`Edit`/`MultiEdit`/`NotebookEdit`) на `.git`/`.worc`/`tasks/` и `--disallowedTools` на `git commit/push`, `gh pr create/merge`.
- **Конверт безопасности.** `sandbox.enabled: false` в него не входит и его не ослабляет: это ключ в файле настроек, а не флаг полного доступа — он не даёт ни одобрений без спроса, ни отключения хуков. `--dangerously*`, `--yolo`, `danger-full-access`, `bypassPermissions` остаются запрещёнными абсолютно на всех трёх слоях.
- **`strict_isolation: true`** — без изменений, песочница там остаётся.

## Асимметрия с Codex, которую надо записать

На Codex так не выйдет. Он всегда получает сгенерированный профиль (`read-only` / `workspace-write`), а `danger-full-access` запрещён абсолютно на трёх слоях — и снимать этот запрет решение **не** предлагает. Значит «никаких ограничений» в режиме будет верно для Claude и неверно для Codex: там останется профильная песочница.

Это надо сказать в носителях режима явно, иначе обещание опять разойдётся с поведением. Отдельного решения по Codex не принимается — вопрос остаётся открытым.
